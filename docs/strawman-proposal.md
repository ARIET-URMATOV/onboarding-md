# Strawman-пропозал: пробелы и рекомендации (до получения ТЗ)

> Дата: 2026-08-31 · Статус: предварительный анализ, ожидается ТЗ от проектных менеджеров.
> Назначение: сверить с реальным ТЗ и использовать как основу для планирования итераций.

## Текущее состояние (инвентаризация)

### Что реализовано
- **Модели**: только `User` и `Progress` (`backend/app/models.py`). Этапы/задачи — hardcoded константы в `stages_data.py` и на фронте, в БД не хранятся.
- **Auth**: открытая саморегистрация, bcrypt, JWT в httpOnly cookie `md_token` (30 дней), демо-аккаунт с ресетом. Роль = только профессия (frontend/backend/design). Нет: админ-ролей, подтверждения email, сброса пароля, refresh-токенов.
- **Прогресс/XP**: серверный пересчёт XP из `done_tasks` (макс 1540 = Lv.16); уровень считается только на клиенте. Нет лидерборда, нет серверного события завершения.
- **Этапы (демо-контент)**:
  - Этап 1 «Документы»: NDA/трудовой договор — **фиктивный JSX-текст** в `Stage1Documents.tsx` / `DocumentModal.tsx`; scroll-gate только на клиенте; mPlus — мок-файл; Jira/Confluence — `*.mdigital.mock`.
  - Этап 2 «Команда»: статичные карточки вымышленных сотрудников.
  - Этап 3 «Видео»: placeholder-видео (w3schools), `onVideoEnded` по событию `ended`.
  - Этап 4 «Чек-лист»: ссылки `href="#"` — декоративные.
  - Этап 5 «Тест»: ссылки на `example.com`, теста в приложении нет.
- **Завершение**: `/complete` доступна только по ручной навигации, автоперехода при 100% нет.

### Чего нет совсем (поиск по кодовой базе — 0 совпадений)
Админ-панель / CMS · хранение и выдача документов (PDF) · подписи/акцепты (кроме таска `1-docs`) · email-отправка, уведомления, дедлайны · LDAP / Active Directory / SSO / OAuth / Keycloak («SSO» и «HR» — только фиктивный текст) · лидерборд · фронтенд-тесты.

## Рекомендации

### 1. Документы + подтверждения (NDA, privacy policy) — ядро
Проблема: текущий NDA — текст в React-компоненте, факт «прочитал/согласен» нигде не фиксируется юридически.

- Модель `Document`: название, тип (NDA / privacy policy / трудовой договор), **версия**, контент или файл.
- Модель `Acknowledgment`: user_id, document_id, **версия документа**, timestamp, IP → юридический аудит-след («кто, какую версию, когда»).
- Принятие: просмотр реального документа + click-to-accept (галка + ввод полного имени). Полная ЭЦП — отдельный проект через HR-портал.

### 2. AD-аутентификация — через абстракцию провайдера
Инфраструктура MDIGITAL неизвестна (выяснить у ИТ). Решение: **не ломать текущую auth**, добавить `auth_provider` в `User`, выделить интерфейс провайдера. При первом входе через провайдера — JIT-создание пользователя из атрибутов каталога (mail, displayName), без пароля в БД. Ограничение — через AD security group; маппинг групп → роль (frontend/backend/design) с автозаполнением шага `/role`.

| Вариант | Когда подходит | Сложность |
|---|---|---|
| LDAP bind (`ldap3`) | on-prem AD; пользователь вводит доменный логин/пароль в ту же форму | низкая |
| OIDC/SSO redirect | Microsoft 365 / Entra ID или Keycloak; redirect-flow, нужен app registration | средняя |

Фронтенд при LDAP не меняется вовсе; при OIDC — кнопка «Войти через корп. аккаунт».

### 3. Админ/HR-панель — итерация 2
Загрузка документов/версий, редактирование контента этапов, просмотр прогресса сотрудников (кто где застрял), экспорт. Без неё смена версии NDA = правка кода + деплой.

### 4. Реальный контент — нужен от компании
- Механизм финального теста (вопросы в БД/конфиге, серверная проверка ответов, «1 попытка»).
- Реальные ссылки этапа 4 (repo, Figma, mail, style guide) — желательно в конфиг, а не в JSX.
- Реальное видео этапа 3, реальный автопереход на `/complete` + уведомление HR.

### 5. Мелкие пробелы — бэклог
Сброс пароля, подтверждение email, дедлайны по этапам, поля профиля (отдел, дата выхода, руководитель), email-уведомления.

## Предложенный раунд 1
1. Backend: `Document` + `Acknowledgment` + эндпоинты (список, контент, accept).
2. Backend: `auth_provider` + абстракция провайдера (локальная auth работает как сейчас).
3. Frontend: модалки этапа 1 грузят документы из API; accept → запись Acknowledgment → таск `1-docs`.
4. Тесты на всё перечисленное.

Отложено: админ-панель, тест-движок, ЭЦП, email/уведомления, LDAP/OIDC (до ответа ИТ).
